Temporal workflow design — RLOS journey
RLOSWorkflow starts (1 per customer)
↓ child workflow
Step 1
IdentityWorkflow
wait signal → verify ID → Nafath/eKYC → parallel fraud check
↓ child workflow
Step 2
OfferWorkflow
parallel: bureau + compliance + fraud → calc offer → wait signal
↓ child workflow
Step 3
TradeWorkflow
Murabaha execution (SA/UAE/BH/KW) or agreement (IN) → wait confirm
↓ child workflow
Step 4
SignatureWorkflow
send eSign → wait up to 48h → reminder at 24h → wait signal
↓ child workflow
Step 5
DisbursementWorkflow
validate IBAN → call core banking → saga rollback if fails
↓
Journey complete — disbursed

Security & compliance design
Authentication & access
JWT tokens — 15 min expiry, refresh via Redis
Stateless auth, revokable via Redis blacklist
mTLS between internal services
Temporal ↔ workers ↔ FastAPI all mutual TLS
API key rotation every 90 days
Claude, ElevenLabs, Whisper — all rotated
RBAC on internal dashboards
Temporal UI, monitoring — role-gated access
Data protection
PII stored only as hashed values
ID numbers, phone, account — SHA-256 hashed
Encryption at rest — AES-256
PostgreSQL, MongoDB, S3 all encrypted
TLS 1.3 in transit everywhere
No plaintext communication between any services
Data residency per region
SA data stays in KSA, IN data stays in India
Compliance — by regulator
SAMA — PDPL data privacy law
Consent capture, right to deletion, data logs
RBI — KYC norms + Fair Practices Code
PAN mandatory >INR 50k, audit trail mandatory
CBUAE — cooling-off period disclosure
Customer notified of right to cancel
Full audit trail — immutable log
Every state change in audit_trail table, hash-chained
Threat mitigation
Rate limiting — Nginx + Redis
100 req/min per IP, 10 auth attempts/hour
Prompt injection protection
System prompt locked, user input sandboxed
Voice deepfake detection
Nafath/UAE Pass as ground truth — not voice alone
Daily automated backups
pg_dump to encrypted S3, 90-day retention
